# حزمة إصلاح MobiHub — 18 نوفمبر 2026

هذه الحزمة مبنية على الملفات الخمسة التي أرسلها المستخدم، مع إصلاحات محددة ومحافظة على أسماء الـ IDs والـ classes وعقود الـ API الحالية.

## محتويات الحزمة

- `app.js` — واجهة Mini App وربط API.
- `index.html` — هيكل Mini App.
- `styles.css` — تصميم Mini App ولوحة الإدارة.
- `Code.gs` — API الخاص بالـ Mini App (الملف الأصلي يصف المشروع بأنه TEST spreadsheet).
- `Bot.gs` — Telegram Bot Webhook.

## الإصلاحات المنفذة

### app.js
- إضافة مهلة اتصال 30 ثانية مع رسالة واضحة عند انتهاء المهلة.
- التعامل مع استجابة الخادم غير الصالحة أو HTML بدل JSON برسالة مفهومة.
- إرفاق HTTP status وrequestId عند توفرهما لتسهيل تتبع الأخطاء.
- منع بيانات `extra` من استبدال `initData` أو `workspaceRole` أو `action`.

### Code.gs
- نقل فحص تكرار Chat ID وإضافة الموظف إلى داخل ScriptLock لتجنب إنشاء موظفين مكررين عند وصول طلبين متزامنين.
- تطبيق الحماية نفسها عند إنشاء مدير جديد.
- رفض بيانات Telegram Init Data المستقبلية بشكل غير منطقي، مع السماح بانحراف ساعة قدره 30 ثانية، والإبقاء على حد الصلاحية الأصلي 24 ساعة.

### Bot.gs
- جعل حجز Telegram `update_id` ذريًا باستخدام ScriptLock حول فحص CacheService وتحديثه.
- جعل فحص وإضافة توقيع HMAC إلى Replay Cache عملية متزامنة محمية بالقفل.
- إزالة سجل التشخيص الذي كان يطبع تفاصيل فحص HMAC وأطوال التوقيع والسر في السجلات.
- لم يتم تغيير تدفق المحادثات أو قوائم البوت أو قواعد الحضور.

### index.html
- إزالة منع تكبير الصفحة على الهاتف، مع إضافة `viewport-fit=cover` لدعم الشاشات ذات الحواف الآمنة.

### styles.css
- إصلاح النص الزائد داخل تعريف زر تبديل مساحة العمل.
- إضافة مؤشر واضح للتركيز بلوحة المفاتيح `:focus-visible`.
- احترام إعداد تقليل الحركة على مستوى الواجهة.
- الحفاظ على قواعد التصميم الحالية لتجنب كسر المكونات التي يعتمد عليها JavaScript.

## ترتيب النشر الآمن

1. خذ نسخة احتياطية من ملفات Apps Script وجداول Google Sheets قبل أي نشر.
2. اختبر `Code.gs` على مشروع TEST spreadsheet أولًا؛ لا تنقله إلى مشروع الإنتاج قبل اجتياز الاختبارات.
3. اختبر `Bot.gs` في مشروع البوت الحالي بعد حفظ نسخة من الإصدار المنشور. التعديل لا يغير صيغة توقيع Cloudflare ولا أسماء الإعدادات.
4. ارفع `index.html` و`styles.css` و`app.js` معًا إلى نفس مكان الاستضافة، مع الحفاظ على الأسماء والمسارات.
5. نفّذ الاختبارات الواردة أدناه قبل اعتماد الإصدار.

## متطلبات خارج الحزمة

- ملف `logo.webp` المشار إليه في HTML لم يكن ضمن الملفات المرسلة، لذلك لم أُنشئ بديلًا أو أغير مساره.
- ملف Cloudflare Worker غير مرفق؛ لم يتم تعديله. يجب أن يستمر في إرسال `proxy_ts` و`proxy_sig` بالطريقة الحالية وبنفس سر HMAC المتفق عليه مع Apps Script.
- إعدادات Script Properties الحالية يجب أن تبقى كما هي، ولا تضع BOT_TOKEN أو HMAC secret داخل ملفات الواجهة.

## اختبارات تم تنفيذها على الملفات

- اجتاز `app.js` فحص JavaScript syntax باستخدام Node.js.
- اجتاز `Bot.gs` و`Code.gs` فحص JavaScript syntax بعد تمرير نسخة مؤقتة بامتداد `.js` إلى Node.js.
- أقواس CSS متوازنة: 1193 قوس فتح و1193 قوس إغلاق.
- تم فحص 91 استدعاء API حرفيًا في الواجهة؛ جميعها لها حالات مقابلة في `Code.gs` (من أصل 100 حالة API).

هذه فحوصات مصدرية/ساكنة، وليست اختبار تشغيل حي داخل Telegram أو Apps Script. يجب تنفيذ اختبارات القبول أدناه في بيئة TEST.

## اختبارات قبول قبل الإنتاج

- تسجيل الدخول بحساب موظف، مشرف، مدير، وSuper Admin.
- تجربة تبديل مساحة العمل إذا كان الحساب له أكثر من دور.
- إنشاء موظف مرتين بنفس Chat ID، بما في ذلك محاولتان متزامنتان؛ يجب أن يُقبل سجل واحد فقط.
- إنشاء مدير مرتين بنفس Chat ID؛ يجب أن يُقبل سجل واحد فقط.
- تجربة Telegram webhook طبيعي، callback query، وإعادة إرسال update_id نفسه.
- التأكد أن توقيع HMAC الصحيح يمر، والتوقيع المعاد استخدامه أو المنتهي يُرفض.
- تجربة فشل الشبكة واستجابة HTML/غير JSON من API.
- اختبار الواجهة بعروض 360 و390 و430 و768 و1024 بكسل.
- مراجعة كل وحدة إدارية بحساب الصلاحية المناسبة والتأكد من عدم اختفاء وظائف.
