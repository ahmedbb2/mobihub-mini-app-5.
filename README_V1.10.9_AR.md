# MobiHub Mini App V1.10.9 — أجهزة الموظف وأسعار الإصلاح (TEST)

## أساس الإصدار
مبني على V1.10.8 TEST. يحافظ على الحضور والانصراف وGPS، الطلبات والإجازات، السلف والعهد والتسويات، الشكاوى، الخصومات والمكافآت، الأوفر تايم والغياب، إدارة الموظفين والمديرين والورديات، إدارة الأجهزة والفحص المستمر المحفوظ.

## إضافات V1.10.9

### 1. مساحة أجهزة الموظف والفني
- بطاقة «حالة الجهاز» تستدعي `device_list` بدل endpoint القائمة العام.
- الموظف يرى فقط الأجهزة المسندة إليه؛ مسؤول الاستلام يرى الأجهزة التي استلمها؛ المدير يرى الكل وفق API الحالي.
- تفاصيل الجهاز وسجل آخر 30 حركة عبر `device_detail` مع فحص صلاحية الوصول على السيرفر.
- تحديث حالة/مكان الجهاز مع إضافة سجل حركة باستخدام `device_status_update`.
- فتح فحص الجهاز واسترجاع آخر جلسة محفوظة وحفظ Snapshot جديد عبر `device_inspection_get` و`device_inspection_save`.
- السيرفر يظل مصدر الصلاحية؛ لا تعتمد الواجهة على إخفاء الأزرار كوسيلة حماية.

### 2. دليل أسعار الإصلاح
- الأقسام: iPhone قطع الغيار، أعطال بوردة iPhone، Apple Watch، AirPods أسعار الأفراد، AirPods أسعار تجارية.
- عرض 12 موديلًا في الصفحة، وبحث شامل عبر الأقسام بعشر نتائج في الصفحة.
- اختيار موديل يعرض جميع الأعطال/قطع الغيار والأسعار المسجلة كما هي في ملف الأسعار.
- جميع العمليات قراءة فقط، ولا يكتب التطبيق إلى ملف الأسعار.
- يعتمد مصدر الأسعار الخارجي على المعرف الافتراضي الوارد في مواصفات V46 مع السماح باستبداله من Script Property `MOBIHUB_REPAIR_PRICE_SPREADSHEET_ID`.

## التغييرات على واجهة الموظف
- «أجهزتي»: تفاصيل الجهاز، سجل الحركة، تحديث الحالة والمكان، وفحص الجهاز.
- «أسعار الإصلاح»: تصفح الأقسام والموديلات والبحث الشامل وعرض الأسعار.
- تم توفير الدخول إلى أسعار الإصلاح أيضًا من وحدة الأجهزة في مساحة الإدارة.

## فحوصات البناء
تم فحص Syntax لملف Apps Script بعد نسخه إلى امتداد JavaScript، وSyntax للواجهة، وHTML IDs المكررة، واختبارات محاكاة محلية لتقسيم الصفحات والبحث وتصفية صلاحيات عرض الأجهزة.

## اختبارات TEST الحية المطلوبة قبل الاعتماد
1. افتح مساحة مهندس لديه جهاز مسند، وتأكد من ظهور جهازه فقط.
2. افتح تفاصيل الجهاز وتحقق من ظهور سجل الحركة وعدم ظهور بيانات أجهزة فني آخر.
3. حدّث حالة/مكان الجهاز وتأكد من إضافة سطر في `سجل حركة الأجهزة`.
4. افتح الفحص، احفظ بعض النتائج والملاحظات، أغلقه ثم افتحه مرة أخرى وتأكد من استعادة آخر Snapshot.
5. جرّب فنيًا آخر للتأكد من رفض تفاصيل/فحص جهاز غير مسند إليه.
6. افتح أسعار الإصلاح، وجرب الأقسام الخمسة، والتصفح، والبحث العام، وعرض الأسعار.
7. إذا ظهر `REPAIR_PRICE_SOURCE_UNAVAILABLE` أو `REPAIR_PRICE_SHEET_MISSING`، تحقق من مشاركة ملف الأسعار مع حساب مالك مشروع Apps Script TEST، وأن الأوراق المطلوبة موجودة بالأسماء الصحيحة.

## حدود التحقق
- لم يتم نشر الحزمة على Cloudflare أو Apps Script.
- لم يتم تغيير Worker أو Webhook أو Sheets الإنتاج.
- لم يتم إجراء اختبار حي لقراءة ملف أسعار Google Sheets من Apps Script في بيئة المستخدم؛ لذلك يلزم التحقق من صلاحية الحساب وربط الملف قبل اعتماد الأسعار.
- اختبار JavaScript المحلي لا يثبت عمل Google Apps Script أو صلاحيات Google Sheets أو Telegram runtime.

## النشر الاختباري
1. خذ نسخة احتياطية من V1.10.8 TEST.
2. انسخ `Code.gs` إلى مشروع Apps Script TEST نفسه مع الحفاظ على Script Properties `BOT_TOKEN` و`SPREADSHEET_ID`.
3. تأكد أن حساب Apps Script يملك صلاحية Viewer على الأقل لملف الأسعار الخارجي، وEditor على ملف الحضور/التشغيل.
4. انشر إصدار Web App جديدًا في TEST.
5. ارفع `index.html`, `app.js`, `styles.css`, `_headers`, `assets/` إلى استضافة واجهة TEST فقط.
6. لا تغيّر API Worker الحالي ولا Telegram Webhook أثناء الاختبار.

## Rollback
استعد حزمة V1.10.8 TEST السابقة وارجع إلى إصدار Apps Script والواجهة السابقين. لم تُجرَ أي تغييرات على الإنتاج.
