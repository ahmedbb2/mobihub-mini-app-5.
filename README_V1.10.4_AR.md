# MobiHub V1.10.4 — فصل السلف والعهد وإصلاح الإشعارات

## الإصلاحات
- السلفة الشخصية تُسجل في `الطلبات` بنوع `سلفة` طبقًا لمنطق V40.
- طلب سحب مبلغ للمشتريات يظل في `طلبات السحب` كعهدة منفصلة.
- لوحة الإدارة المالية تعرض قائمتين منفصلتين: السلف / السحب والعهد والتسويات.
- حساب Finance يرى ويعتمد طلبات السلفة فقط من جدول الطلبات، ولا يعتمد طلبات الموارد البشرية الأخرى.
- عند تقديم السلفة: تأكيد للموظف + إشعار للمديرين النشطين Super Admin / Admin / Finance.
- عند قرار المدير: إشعار للموظف بالقبول أو الرفض.
- عداد الطلبات المالية المعلقة يشمل السلف والعهد.
- إشعار طلب السحب لا يرسل أزرار callback قديمة غير مدعومة.

## النشر (TEST أولًا)
1. خذ نسخة احتياطية من مشروع Apps Script API ومن Cloudflare Pages.
2. ارفع `index.html`, `styles.css`, `app.js`, `_headers`, ومجلد `assets` إلى Cloudflare Pages.
3. استبدل `Code.gs` في مشروع Mini App API وانشر إصدار Web App جديد.
4. تأكد من Script Properties: `SPREADSHEET_ID`, `BOT_TOKEN` (أو `MOBIHUB_TELEGRAM_BOT_TOKEN`). يمكن ضبط `ADMIN_ID` إن كان رقم المدير الرئيسي مختلفًا عن القيمة الاحتياطية.
5. اختبر طلب سلفة صغيرًا وطلب سحب مبلغ منفصلًا وتأكد من الشيت والإشعارات ولوحة الإدارة.
6. لا تنقل أو تحذف السجلات القديمة تلقائيًا. السجلات التاريخية المختلطة تحتاج مراجعة مستقلة قبل إعادة تصنيفها، خصوصًا لو تمت الموافقة أو الصرف أو التسوية.

## استعادة /start ولوحة Telegram القديمة
لكل Bot Token يوجد Webhook واحد فقط. `doPost(e)` في مشروع Mini App API يستقبل طلبات التطبيق، وليس تحديثات Telegram. يجب أن يشير Telegram Webhook إلى مشروع البوت القديم النشط الذي يحتوي على `doPost(e)` الخاص بمعالجة رسائل Telegram.

1. افتح مشروع Apps Script الخاص بالبوت القديم النشط، وليس مشروع Mini App API.
2. انشره كـ Web App: Execute as Me، وWho has access = Anyone.
3. أضف `LEGACY_BOT_WEBHOOK_REPAIR_V1.10.4.gs` إلى مشروع البوت القديم.
4. شغّل `mobihubCheckTelegramWebhook()` وافحص Execution Log.
5. شغّل `mobihubRestoreTelegramWebhook()` مرة واحدة.
6. أرسل `/start` للبوت. يجب أن يصل إلى `doPost(e)` القديم.
7. تأكد أن دالة `sendMainMenu_` في مشروع البوت القديم تستخدم `{remove_keyboard:true}` للموظفين ولا تعيد إنشاء Reply Keyboard دائمة. نسخة الدالة الصحيحة موجودة في `MobiHub_Attendance_v40_REFERENCE.gs`؛ انقل جسم الدالة فقط إلى المشروع النشط.
8. لإزالة الأزرار القديمة من كل حسابات الموظفين دفعة واحدة، شغّل `mobihubRemoveLegacyKeyboardForAllEmployees()` مرة واحدة من مشروع البوت القديم. هذه العملية ترسل رسالة تحديث واحدة لكل موظف نشط حتى يستطيع Telegram إزالة لوحة المفاتيح من محادثته.

لا تضبط Webhook على رابط Mini App API أو Cloudflare Worker API، ولا تستبدل `doPost(e)` الخاص بالبوت بدالة API الخاصة بالتطبيق.

## حدود الاختبار
- لم يتم نشر الملفات على حسابك أو الاتصال بTelegram/Google Sheets الحي من هنا.
- الإصدار يمنع الخلط في الطلبات الجديدة فقط؛ لا يهاجر الطلبات التاريخية.
- إصلاح Webhook يتطلب تشغيل الدالة من مشروع البوت القديم نفسه.
